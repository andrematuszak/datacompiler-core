ÉTAPE 1/6
🔍 Extraction frontend/extract
Ouverture du PDF avec deux moteurs en parallèle (PyMuPDF + pdfplumber), extraction du texte, de la typographie, des images, des tableaux et des éléments vectoriels, puis fusion dans le modèle Document.
PyMuPDF extraire_page_pymupdf()
Moteur 1 — Texte & Typographie
Extrait les mots (texte + bbox), les polices, la couleur, le gras/italique, les métadonnées du document, et les zones vectorielles (lignes, rects, courbes).
pdfplumber extraire_page_pdfplumber()
Moteur 2 — Graphiques & Vecteurs
Extrait les images (avec sonde de texte), les tableaux (avec reconstruction avancée si dégénérés), et les lignes vectorielles.
Fusion fusionner_page()
Assemblage final
Fusionne les flux PyMuPDF (texte/typo) et pdfplumber (graphiques/tableaux) dans la structure Page du modèle.
Sonde texte image sonder_images_page()
Détection de texte dans les images
Passe Tesseract en mode "sparse text" sur chaque image pendant que le PDF est encore ouvert, pour signaler si une image contient du texte.
Reconstruction tableaux reconstruire()
Repli pour tableaux dégénérés
Reconstruit les colonnes d'un tableau que pdfplumber détecte comme une seule colonne, à partir des points de rupture récurrents des filets horizontaux.
▼Document rempli (native + graphics)
ÉTAPE 2/6
🩺 Diagnostic frontend/diagnostic
Analyse le document extrait (sans rouvrir le PDF) pour évaluer la qualité du texte natif, détecter les anomalies et décider si un OCR est nécessaire.
Intégrité texte qualite_texte()
Qualité du texte natif
Calcule un score de qualité basé sur les caractères suspects (mojibake, PUA) et les tokens anormaux (chiffres dans mots, casse irrégulière).
Angles morts symboles_corrompus()
Corruptions invisibles
Détecte les substitutions de caractères (€ → e, l → t) et les mots suspects par trigrammes internes au document.
Intégrité visuelle couverture_image_max()
Images & DPI
Calcule la couverture image pleine page, le DPI effectif des images, et détecte les images contenant du texte.
Géométrie score_ordre_lecture()
Ordre, chevauchements, limites
Score l'ordre de lecture, détecte les paires de mots chevauchants et les mots hors des limites de la page.
Texte vectorisé zones_texte_vectorise_probable()
Glyphes dessinés
Regroupe les éléments vectoriels denses (lignes, courbes, rects fins) en zones suspectées de contenir du texte dessiné plutôt qu'écrit nativement.
Conteneur producteur_suspect()
Métadonnées du PDF
Vérifie si le producteur/créateur du PDF est dans la liste des producteurs suspects (volontairement vide au départ).
Catégorisation categoriser()
Catégorie unique
Dérive une catégorie : natif_propre, natif_corrompu, natif_mixte ou scan.
Rapport afficher()
Interface humaine
Affiche un résumé lisible du diagnostic dans le terminal.
⚡ doc.diagnostic.recommend_ocr = True si : pas de texte natif, qualité < 0.9, couverture native < 0.9, texte dans image, OCR embarqué détecté, symboles corrompus, ou échantillon trop court.
▼Document diagnostiqué (diagnostic rempli)
ÉTAPE 3/6
🤖 OCR Page Entière frontend/ocr
Si le diagnostic recommande un OCR et que la clé API Mistral est disponible, appelle l'API Mistral pour OCRiser le document entier.
🔀 Condition : doc.diagnostic.recommend_ocr == True ET MISTRAL_API_KEY présente
⚠️ Si OCR recommandé mais pas de clé API → poursuite avec le texte natif (avertissement)
✅ Si OCR non recommandé → étape sautée
MistralBackend ocraliser()
API distante Mistral AI
OCRise le PDF entier en un seul appel API. Remplit page.ocr.words et page.ocr.engine. Ne fournit de bbox qu'au niveau bloc, pas mot.
Registre get_backend()
Registre des backends
BACKENDS = {"mistral": MistralBackend, "tesseract": TesseractBackend} — permet de choisir le backend par nom.
▼page.ocr rempli (si OCR exécuté)
ÉTAPE 4/6
🎯 OCR Ciblé — Zones Vectorisées frontend/ocr/vector_zones
Indépendant de la clé API et du diagnostic global : cible uniquement les zones de texte vectorisé détectées par vector_text.py, et comble les vides géométriques avec Tesseract local.
Récupération texte vectorisé recuperer_texte_vectorise()
OCR ciblé par zone
Pour chaque zone détectée : crop de la zone → OCR Tesseract → filtrage des doublons avec le natif → injection directe dans page.native.words avec is_vectorized=True.
TesseractBackend ocraliser_zone()
OCR local (Tesseract)
Double passe PSM 3 + PSM 6, filtrage du bruit de bordure, filtrage des pictogrammes par géométrie, bbox par mot avec confiance.
Fusion multi-backend fusionner_candidats_ocr()
Arbitrage entre backends OCR
En cas de chevauchement de bbox entre deux backends, garde celui de plus haute confiance. Trace chaque arbitrage dans notes.
▼native.words enrichi (is_vectorized=True)
ÉTAPE 5/6
⚙️ Compilation / Arbitrage compile
Résout chaque page : ordre de lecture réel, normalisation typographique, alignement natif ↔ OCR, résolution des conflits, regroupement en lignes et QA.
1. Ordre de lecture reading_order.ordonner()
Boîtes → Rangées → Tri
Construit des boîtes par ligne physique (native + vectorisée), les regroupe en rangées par chevauchement vertical, trie chaque rangée gauche → droite. Les mots de tableaux sont exclus puis réintégrés.
2. Typographie typography.normaliser()
Ligatures + césures
Normalise les ligatures Unicode (ff, fi, fl, ffi, ffl, st) et fusionne les mots coupés par une césure de fin de ligne.
3. Alignement alignment.aligner()
Diff natif ↔ OCR
Aligne les séquences de texte natif et OCR avec difflib.SequenceMatcher (autojunk=False). Produit des UniteAlignement : equal, conflit, natif_seul, ocr_seul.
4. Résolution conflits conflict_resolution.resoudre_page()
Texte final par unité
La bbox vient toujours du natif. En cas de conflit, compare les confiances (heuristique native vs OCR) et choisit le texte le plus fiable. Interpole les bbox des mots ocr_seul.
5. Lignes layout.assigner_lignes()
Regroupement en lignes visuelles
Annote chaque mot avec layout_line (numéro de ligne) en détectant les sauts de ligne par tolérance sur y0.
6. QA qa.annoter()
Détection d'anomalies
Ajoute des Flag : confiance basse (< 0.6) et ordre suspect (saut arrière en y0). Ne modifie jamais texte ni bbox.
Confiance confidence.meilleur()
Échelle commune [0,1]
Estime la confiance native (heuristique : caractères suspects, chiffres, casse) et OCR (confidence fournie ou 0.5 par défaut). Écart significatif ≥ 0.15.
▼page.resolved rempli (words + images + tables)
ÉTAPE 6/6
📦 Rendu backend
Rend le document résolu dans le format de sortie choisi selon la stratégie.
PDF Fidèle render_faithful_pdf()
3 stratégies
• overlay : superpose une couche invisible sur le PDF source
• clean_overlay : recrée la page (images + dessins) et réinjecte le texte résolu
• rasterized : rasterise chaque page en image + couche invisible
PDF Flow render_flow_pdf()
Flux texte linéaire
Reflue le contenu comme un traitement de texte : marges fixes, lignes empilées dans l'ordre de lecture, pages A4.
PDF Reconstruit render_rebuilt_pdf()
Texte visible et sélectionnable
Reconstruit un PDF neuf à la même position que le source. Copie images/dessins (en excluant les glyphes vectorisés), calibre les lignes de base, échantillonne les couleurs, utilise LiberationSans.
Markdown render_markdown()
Rendu texte
Un titre par page, un paragraphe par ligne regroupée, tableaux en syntaxe Markdown.
HTML render_html()
Rendu web
Document Flow : empilement en ordre de lecture, hauteur libre, tableaux en HTML.
DOCX render_docx()
Rendu Word
Un titre par page, un paragraphe par ligne, vrais tableaux Word avec style "Table Grid".

📋 Flux de données entre les modules

Étape Module Fichier(s) Entrée → Sortie
1 Extraction frontend/extract/__init__.py PDF path → Document (native.words, graphics, metadata)
1a PyMuPDF frontend/extract/pymupdf.py fitz.Page → Page (native.words, fonts, graphics.lines/rects/curves)
1b pdfplumber frontend/extract/pdfplumber.py pdfplumber.Page → graphics_data (images, tables, lines)
1c Fusion frontend/extract/merge.py Page + graphics_data → Page complète
2 Diagnostic frontend/diagnostic/__init__.py Document → Document (diagnostic rempli, recommend_ocr)
3 OCR page entière frontend/ocr/__init__.py Document + PDF → Document (page.ocr.words, page.ocr.engine)
4 OCR ciblé frontend/ocr/vector_zones.py Document + PDF → Document (native.words enrichi, is_vectorized=True)
5 Compilation compile/compiler.py Document → Document (page.resolved.words, images, tables)
5a Ordre de lecture compile/reading_order.py page.native.words → copies ordonnées (boîtes/rangées)
5b Typographie compile/typography.py mots ordonnés → mots normalisés (ligatures, césures)
5c Alignement compile/alignment.py mots natifs + mots OCR → UniteAlignement[]
5d Résolution conflits compile/conflict_resolution.py UniteAlignement[] → resolved.words (texte final + bbox)
5e Lignes compile/layout.py resolved.words → annoté avec layout_line
5f QA compile/qa.py resolved.words → annoté avec flags (confiance, ordre)
6 Rendu backend/__init__.py Document → fichier de sortie (PDF/MD/HTML/DOCX)
— Modèle model/document.py Word, Page, Document, NativeContainer, OcrContainer, ResolvedContainer
— Heuristiques heuristics.py Signaux bas niveau partagés (diagnostic + confidence)
